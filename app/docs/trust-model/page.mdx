# Trust model

<Lede>
Precision here matters more than marketing. Dara makes a narrow claim and defends it, rather
than a broad claim it cannot support.
</Lede>

## The claim

> Dara gives a team internal accountability and reproducibility over its own generated media,
> and gives that team's clients a disclosure record they can check.

## The boundary

<Callout type="danger" title="Tamper-evident, not tamper-proof">
Dara is authoritative **inside** an organisation that controls its own B2 bucket. Anyone who
controls that storage controls the record. Against a hostile third party, Dara proves nothing
on its own — C2PA or an external signer is the right next layer.
</Callout>

Stated as a table, because vagueness here would be dishonest:

| Question | Dara answers it? |
|---|---|
| Did these bytes come from a run we recorded? | **Yes**, if we hold the record |
| Were these bytes modified after we published them? | **Yes** |
| Is this manifest internally consistent? | **Yes**, independently of our storage |
| Was this generated by AI at all? | **No** |
| Is this file authentic, to someone who does not trust us? | **No** |

## The five verification states

None of them is a dead end, and none overclaims.

| State | Meaning |
|---|---|
| `trusted-match` | Manifest is valid and the whole-file hash matches our published record |
| `trusted-mismatch` | A record exists, but these bytes are not it |
| `self-consistent` | The manifest validates, but we hold no record. **Not** verified |
| `matched-by-hash` | No manifest, but the content hash matched a known asset |
| `unknown` | No record. It may have been generated elsewhere, or modified after generation |

The API's `result` field describes *how* provenance was discovered; `verification` carries the
trust state above. Conflating those two would be the easiest way to mislead someone, so they
are kept separate.

## Degradation is not a verdict

If trusted storage cannot be reached, Dara reports `self-consistent` with an explicit storage
warning. It does **not** guess, and it does not report `unknown` — because "we could not check"
and "we checked and found nothing" are different statements.

A hash-only lookup cannot be classified without storage at all, so it returns a retryable
error instead of a misleading answer.
