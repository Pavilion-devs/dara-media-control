## The QA loop

An agent scores the output against a rubric. Below threshold, it rewrites the prompt and tries
again, up to the attempt budget the policy allows.

What makes this more than a retry: **every attempt is preserved**. A rejected candidate keeps
its row, its score, and its link to the parent run, so the version tree shows what actually
happened rather than a tidied summary.

<Callout type="note" title="Reproducible conditions, not identical bytes">
Media models are generally non-deterministic. Regeneration replays canonical parameters and
records lineage — it does not promise the same output, and Dara does not claim it does.
</Callout>

## Fallback chains

When a primary model fails, the pipeline attempts the next route in the chain. Both the failure
and the recovery are recorded; the run does not silently look like a first-attempt success.

Image generation is provider-diverse — OpenAI primary, Replicate as a genuinely different
provider. Video and speech currently use same-provider fallbacks, which is stated plainly
rather than dressed up.

## Streaming

Progress is streamed over SSE from `GET /v1/runs/{job_id}/events`, with polling as a fallback
if the stream drops. The client reconnects with `?after_seq=N` so no event is replayed twice.
